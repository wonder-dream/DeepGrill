## 一句话边界

面向大众的 **AI 模拟面试平台**，核心是「AI 面试官」这一角色 —— 而不是面向单一岗位的个人刷题工具。
账号名额的硬性上限只为一件事存在：**控制 LLM 开销**。它是成本阀门，不是产品定位（不许把它当作"内测""小圈子"来论证任何设计取舍）。
_Avoid_: 刷题工具、personal tool、demo、内测产品

## In（v2 要做）

### 产品形态
三种，共享同一个**面试官**（区别于 v1：v1 只有「单题 + 追问」一种）：

| 形态 | 编排 | 额度点 | 输出 |
|---|---|---|---|
| **模拟面试** | 抽多题 → 逐题提问 → 每题追问 2-3 轮 → 收尾 | 6 | 面试总报告 |
| **单题追问** | 单题挖到深处 | 1 | 单题评分 + 反馈 |
| **题库刷题** | 自选题目，无 LLM | 0 | 自测；可看题干与评分标准 |

**模拟面试只有文字输出一种模态。** 语音输出（面试官 TTS 说话 + AI 数字人）已于决策 31**移出** —— 它的成本是文字输出的 10-30 倍，见下文「已评估但暂缓」。

**但语音输入要做**（决策 32）：面试页可语音回答，默认语音、可随时切回打字。这是**模拟面试真实感的关键** —— 打字框允许反复修改措辞，而真实面试考的是临场组织语言；v1 的 `clarity` 维度在打字模式下测的是排版，不是表达。

**语音输入不设「确认」这一步**（决策 33）：转写直接进判分，用户拿起麦克风就说话，没有"核对一遍再交"的环节 —— **术语识别错误交给 STT 模型与下游 LLM 的质量本身解决**，不靠人工核对兜底。判断候选人答得对不对、术语用没用对，本来就要读懂整段话；而"让用户先确认一遍"是把语音省下的打字成本又还回去。

首页 = **内容推荐中心**：开始模拟面试（主按钮）+ 今日推荐题 + 我的私有题集 + 继续未完成会话。**不做学习路径状态机。**

> ⚠️ **「今日推荐题」是即时计算，不是每日锁定的题单**：`user_picks` 与 `questions.selected_at` 都随之删掉（见 `docs/v2数据模型.md`）—— 「今日题」作为**每日配额制的产物**消失了，而首页那个位置改由**按掌握度薄弱点现算**的推荐填充。它没有自己的表，也不跨天固化；换成别的推荐算法时它不会留数据残骸。

### 内容
- **收藏夹**：候选人可以在**题库**里收藏题目，是首页的一个入口。收藏是**用户自己的指针**（`user_favorites`），题本身不动；动作幂等（`UNIQUE(user_id, question_id)`），**不消耗额度点**
- 内容来源三类：**种子题**（从 v1 迁移的题目 + 其题目级 `good_criteria`/`bad_criteria`）、**生成题**（LLM）、**晋升题**（用户私有题转入）
- 门禁：**自动门禁进池 + 事后治理**（人工不再前置逐题审）
- 知识层：**三层**，层级与表结构见 `docs/v2数据模型.md`；**岗位是独立的另一条轴、不在层级里**（决策 51/52）；骨架由 LLM 提议、**人审核**；挂题由 LLM 自动完成、靠答题数据自纠
- 每道题必须有一个**主知识点**（另可有 0..N 个**关联知识点** —— 决策 24）
- 知识层内容只有三类：骨架、知识点定义（1-2 行考察点）、泛用题的**参考答案**；**讲解/讲义按需生成 + 缓存，不预生成、不进审核队列**
- **不保留任何文档库**（v1 那批爬来的知识块整批丢弃，数量见 `docs/v1现状-20260913.md`）

### 简历与隐私
- 上传简历 → **解析成结构化候选人档案**（不保存简历原文）→ 生成**私有题集** → 面试从私有题集抽题
- 私有题集**用户隔离**；用户可主动**晋升**单题到公共题库（经内容门禁）

### 身份与成本
- 面向公众开放；**账号名额上限**是**成本阀门**（初期 10-20 人）
- **注册 = 邀请码**（后台生成、可设有效期、可作废回收）+ 邮箱作为登录名 + 密码；**不做邮箱验证码、不需要 SMTP**
- 忘密码 = 管理员后台重置；必须提供**注销账号与数据**入口（公开产品的法律底线）
- 额度 = **单一额度点**；耗尽后**降级**为纯题库模式（题库仍可用），不做硬拒绝
- 后台同时记录真实 token 开销作第二道安全网
- 模型：**统一 `deepseek-v4.1-flash`**（v1 的 `deepseek-chat`/`deepseek-reasoner` 已废弃）

### 部署与基础设施
> **本节只写范围** —— 决策、理由与它反推出的硬要求清单的权威处在 **ADR-0008**，本节不复述。

- 目标机器：**境外（美东弗吉尼亚）2C2G（上限 4C8G）单机**；因无法备案而选境外
- 网络与 TLS：Cloudflare 做 CDN 与访客 TLS，源站保持可移植
- 传输层：**TLS 是上线前置条件，不是待办**
- 存储：**SQLite + WAL**（调低页缓存）
- 备份：定时异地备份到对象存储，且**必须验证「能恢复」**

### 架构
> **本节只列索引** —— 每条结论的权威定义在对应 ADR 里，本节不复述。

- 面试官是 **workflow（带循环的状态机）而非自主 Agent**；追问驱动 = 探测候选人的能力边界 → **ADR-0001**
- 知识层 = 关系库里的**森林 / DAG**，不用图数据库 → **ADR-0002**
- 面试报告由数据拼装，只有一段总结由 LLM 生成 → **ADR-0003**
- 前端**服务端渲染为主**，浏览器只负责面试页 → **ADR-0004**
- 代码**按领域切分、依赖单向**，跨领域动作归上层 → **ADR-0005**
- 离线任务用 **jobs 表 + 独立 worker**，不用 Redis → **ADR-0006**
- **prompt 独立成文件** → **ADR-0007**
- 部署在**境外单机**，Cloudflare + 源站可移植 → **ADR-0008**
- 嵌入**走 API**；删除本地模型 / 向量库 / 单进程锁；运行时只在「简历文本 → 知识点」一处用向量召回
- 交互：**SSE 流式**输出面试官说的话；**思考过程不展示**（但服务端记录用于调试）
- 从零重写：代码与架构全新；v1 的行为契约见 `docs/v1行为规格.md`

## Out（v2 明确不做）

| 不做 | 原因 |
|---|---|
| 爬虫（GitHub 采集、牛客采集、许可白名单、来源溯源、手写导入 CLI） | 面向公众后第三方内容的再分发风险无法靠代码消除；牛客源 v1 自己已放弃适配 |
| 人工前置逐题审核 | 吞吐瓶颈；改为自动门禁 + 事后治理 |
| 学习路径状态机 / 强制流程 | 用户随时可能只想刷两道题 |
| 本地向量库 / 本地嵌入模型 | 3000 条数据的全量点积是毫秒级；FAISS 解决的不是这个问题 |
| 独立知识库（文档切块 + 检索） | 被知识点定义取代 |
| 图数据库（Neo4j） | 几百个节点在内存里就是个字典 |
| 多向量库 / 多 embedding provider 的抽象层 | 没有第二个使用场景 |
| 内容管理 UI（分类/标签增删改） | v1 的 `admin/categories`/`admin/tags` 6 个端点随之消失 |
| 展示 LLM 思考过程 | 已明确 |
| **语音输出 / AI 数字人（TTS + 头像）**（决策 31 移出） | **技术上可行、已查实单价，但成本是文字输出的 10-30 倍**（一场约 0.6-1.7 元 vs 0.06 元）。注意：**语音输出的成本几乎全在 TTS，STT 便宜到可忽略** —— 所以只做语音输入（决策 32）不受此限。详见下文「已评估但暂缓」 |

## 换模型的影响范围（决策 50 的连带纪律）

按用途分开命名之后，「换模型」这件事的影响范围才是明确的：

| 换哪个 | 必须做什么 |
|---|---|
| `MODEL_INTERVIEWER` | **面试官相关的 prompt 全部重测**（追问、判分）—— 换模型必须重测 prompt，这是 `v1行为规格.md` §4.10 已定的纪律 |
| `MODEL_OFFLINE` | 聚类 / 挂载 / 生成 / 质检的 prompt 重测 |
| `MODEL_EMBED` | 不需要重测 prompt，但**全部已存向量作废、必须重算** |

⚠️ **最后一条最容易被忘记，而且它不报错**：嵌入模型一换，库里旧向量与新算向量**不在同一向量空间**，相似度比较会静默给出垃圾结果。所以换嵌入模型时必须有一个「重算全部向量」的步骤，而不是只改配置值。

## 已评估但暂缓：语音输出（面试官 TTS / AI 数字人）

> **决策与形态判断的权威在 ADR-0009** —— 本节只留成本证据与实施坑清单，不复述决策。

**注意：暂缓的是「语音输出」，不是「语音」。语音输入要做**（决策 32）。两者成本差 13 倍，见下表。

### 关键区分：贵的是 TTS，不是 STT

```
语音输入（用户说 → 转写）    STT  8 分钟 ≈ 0.13 元/场  ← 便宜到可忽略
语音输出（面试官说 → 朗读）  TTS  3000 字 ≈ 0.24-1.50 元/场  ← 成本几乎全在这里
```

**所以「暂缓语音输出」不影响「做语音输入」。**

### 形态判断（若将来做）

「数字人」三个字背后是差别极大的三种东西：**音频 + 会动的头像**（CSS 动画，近零成本）／**音频 + 口型同步**（Live2D 级）／**真数字人视频**（按分钟计费，单场可能几美元）。**选前者** —— 面试的紧张感来自"要说出口"，不来自"看得到嘴型"。

### 真实单价与成本（决策 31 查实）

| 项 | 服务商与单价 | 一场 15 分钟的成本 |
|---|---|---|
| **STT** | 豆包流式语音识别 2.0：**1 元/小时** | 用户说 8 分钟 ≈ **0.13 元** |
| **TTS（贵档）** | 豆包大模型语音合成：**5 元/万字符** | 面试官说 3000 字 ≈ **1.50 元** |
| **TTS（中档）** | 豆包语音合成 2.0：**3 元/万字符** | ≈ 0.90 元 |
| **TTS（便宜档）** | 阿里 qwen3-tts-flash：**0.1147 USD/万字符** ≈ 0.83 元/万字符 | ≈ **0.24 元** |
| LLM | deepseek-v4.1-flash（已有） | ≈ 0.06 元 |

**关键发现：TTS 是唯一的成本大头，且不同档次差 5-6 倍；STT 便宜到可以忽略。**

| 组合 | 一场成本 | 20 人 × 每日 1 场 = 每月 |
|---|---|---|
| 豆包 + 大模型 TTS | ~1.7 元 | **约 1000 元** |
| 阿里 qwen3-tts | ~0.6 元 | 约 360 元 |
| **纯文字（对照）** | **~0.06 元** | 约 36 元 |

**语音把成本乘以 10-30 倍** —— 而「10-20 个名额」这个成本阀门是按文字算的。

### 实施时需要注意的坑（若将来重启）

- **并发要买**：豆包默认并发 5-50 路，超出 **100 元/并发/月**
- **音色可能收费**：音色槽位 138 元/音色起 —— 但**赠送音色免费**，只需要"一个面试官的声音"，**不要复刻音色**
- **确认流式**：阿里 qwen3-tts-flash 标注为「**离线**语音合成」，若只有非流式接口，首句要等整段合成完，延迟会明显劣化 → 需确认是否支持流式
- **网络路径是隐藏硬约束**：服务器在美东、用户在境内，语音是双向实时流。绕美国会明显劣化 → 大概率需要**客户端直连语音服务**（绕过应用服务器），而这要求服务商支持前端鉴权（临时凭证 / 签名）
- **必须处理「用户打断面试官」**：语音交互里最容易被忽略、但不处理就假得刺眼的地方

### 它动摇过哪些已定决策（记录，供将来重启时参考）

| 已定决策 | 若做语音的影响 |
|---|---|
| 统一 `deepseek-v4.1-flash` | ❌ **不够** —— DeepSeek 无 STT/TTS，必须引入语音服务商（第 2、3 个外部依赖） |
| 额度点单一记账（面试 6 / 追问 1） | ⚠️ **要重定** —— 语音成本是文本的数倍，混在一个池子里用户看不懂 |

| 2C2G 服务器 | ⚠️ **本地语音模型不可行**（Whisper 级模型内存不够）→ 必须走 API |

## 掌握度的定义（决策 24 的结论，重要）

```
掌握度矩阵的每一格 = 该知识点下「被考过的考察点」里，候选人答到了多少
                    （不是分数，也不是题量）

它只依赖 hits（逐轮产出），与「这道题挂在知识地图的哪个节点下」无关。
```

三条推论：

1. **「没考过」是空格，「考了但没答」是 0%** —— 两者对候选人的含义完全不同，必须可区分。这要求命中记录在用户完全没答时也要记未命中，而不是只在答到时才有数据。
2. **一道综合题会同时填充多个格子** —— 库里真题 1065（设计一个可靠的 Agent 系统，要求支持幂等/熔断/限流/成本/权限/可观测）一道题就能在六个知识点上留下记录。
3. **不需要给「题目 ↔ 知识点」的关联加权** —— 权重问题被「格子装命中率而非分数」消解掉了。
