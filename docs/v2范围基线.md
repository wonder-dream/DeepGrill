# DeepGrill v2 范围基线

> 本文件是 v2 的**产品与架构边界**。它存在的原因是 v1 的根因诊断（`v1现状-20260913.md` §6-P2）：5 周内 8 次方向性反转，导致 `routes.py` 长到 3033 行。
> **规则：v2 开发期间，任何功能增删都必须先改本文件，再动代码。** 未列入「In」的一律不做。
> 状态：起草中（决策已到第 24 轮），未冻结。

## 一句话边界

面向大众的 **AI 模拟面试平台**，核心是「AI 面试官」这一角色 —— 而不是面向单一岗位的个人刷题工具。
账号名额的硬性上限只为一件事存在：**控制 LLM 开销**。它是成本阀门，不是产品定位（不许把它当作"内测""小圈子"来论证任何设计取舍）。
_Avoid_: 刷题工具、personal tool、demo、内测产品

## In（v2 要做）

### 产品形态
三种，共享同一个**面试官**（区别于 v1：v1 只有「单题 + 追问」一种）：

| 形态 | 编排 | 额度点 | 输出 |
|---|---|---|---|
| **模拟面试** | 抽多题 → 逐题提问 → 每题追问 2-3 轮 → 收尾 | 6 | 面试总报告 |
| **单题追问** | 单题挖到深处 | 1 | 单题评分 + 反馈 |
| **题库刷题** | 自选题目，无 LLM | 0 | 自测；可看题干与评分标准 |

首页 = **内容推荐中心**：开始模拟面试（主按钮）+ 今日推荐题 + 我的私有题集 + 继续未完成会话。**不做学习路径状态机。**

### 内容
- 内容来源三类：**种子题**（从 v1 迁移的 3009 道 + 其 `good_criteria`/`bad_criteria`）、**生成题**（LLM）、**晋升题**（用户私有题转入）
- 门禁：**自动门禁进池 + 事后治理**（人工不再前置逐题审）
- 知识层：**关系库里的图** —— 岗位 → 知识领域 → 知识点（+ 前置依赖）；骨架由 LLM 提议、**人审核**；挂题由 LLM 自动完成、靠答题数据自纠
- 每道题必须归属一个**知识点**
- 知识层内容只有三类：骨架、知识点定义（1-2 行考察点）、泛用题的**参考答案**；**讲解/讲义按需生成 + 缓存，不预生成、不进审核队列**
- **不保留任何文档库**（v1 的 2503 个知识块丢弃）

### 简历与隐私
- 上传简历 → **解析成结构化候选人档案**（不保存简历原文）→ 生成**私有题集** → 面试从私有题集抽题
- 私有题集**用户隔离**；用户可主动**晋升**单题到公共题库（经内容门禁）

### 身份与成本
- 面向公众开放；**账号名额上限**是成本阀门（初期 10-20）
- **注册 = 邀请码**（后台生成、可设有效期、可作废回收）+ 邮箱作为登录名 + 密码；**不做邮箱验证码、不需要 SMTP**
- 忘密码 = 管理员后台重置；必须提供**注销账号与数据**入口（公开产品的法律底线）
- 额度 = **单一额度点**；耗尽后**降级**为纯题库模式（题库仍可用），不做硬拒绝
- 后台同时记录真实 token 开销作第二道安全网
- 模型：**统一 `deepseek-v4.1-flash`**（v1 的 `deepseek-chat`/`deepseek-reasoner` 已废弃）

### 部署与基础设施
- 目标机器：**境外（美东弗吉尼亚）2C2G（上限 4C8G）单机**；因无法备案而选境外
- **这一约束反推出一批硬要求**：
  - **嵌入必须走 API** —— 本地 bge-m3 需 ~2.3GB 常驻内存，在 2C2G 上根本跑不起来（v1 的部署方式在这台机器上不成立）
  - **禁止全量加载大表** —— v1 的「全表 embedding 拉成矩阵」在 2G 内存上是定时炸弹
  - 境内直连美东 RTT 200-300ms → 静态资源强缓存 + 压缩；SSE 每 token 跨境一个来回
- 网络：**Cloudflare 免费版**做 CDN + 隐藏源站 + 访客侧 TLS；**源站保持可移植**（Caddy 同时具备直连 Let's Encrypt 能力，CF 不可达时只需改 DNS）
- 源站 TLS：优先 **Cloudflare Origin Certificate**（免 ACME、长有效期，消除证书续期这个静默故障源）
- 传输层：**TLS 是 v2 上线前置条件，不是待办**（v1 裸奔在 8000 端口）
- 存储：**SQLite + WAL**（调低页缓存）；Postgres 在 2G 机器上多占约 200MB 常驻内存，而 20 用户碰不到 SQLite 写并发瓶颈
- 备份：**定时异地备份到对象存储**（R2/B2 级别）；数据库与机器同生共死是当前最大单点风险（v1 已发生过一次整库覆盖冲掉 users）
- **备份必须验证「能恢复」**，不只是「有文件」（v1 的备份机制从未被真实恢复过）

### 架构
- 面试官 = **编排层（硬约束）+ 单一引擎（单题内自主）** —— 按行业标准定义，这是一个 **workflow（带循环的状态机）而非自主 Agent**；追问驱动 = 探测候选人的能力边界（ADR-0001）
- 知识层 = 关系库里的图，不用图数据库（ADR-0002）
- 嵌入**走 API**；删除本地模型 / 向量库 / 单进程锁；运行时只在「简历文本 → 知识点」一处用向量召回
- 交互：**SSE 流式**输出面试官说的话；**思考过程不展示**（但服务端记录用于调试）
- 从零重写：代码与架构全新；v1 的行为契约见 `v1行为规格.md`

## Out（v2 明确不做）

| 不做 | 原因 |
|---|---|
| 爬虫（GitHub 采集、牛客采集、许可白名单、来源溯源、手写导入 CLI） | 面向公众后第三方内容的再分发风险无法靠代码消除；牛客源 v1 自己已放弃适配 |
| 人工前置逐题审核 | 吞吐瓶颈；改为自动门禁 + 事后治理 |
| 学习路径状态机 / 强制流程 | 用户随时可能只想刷两道题 |
| 本地向量库 / 本地嵌入模型 | 3000 条数据的全量点积是毫秒级；FAISS 解决的不是这个问题 |
| 独立知识库（文档切块 + 检索） | 被知识点定义取代 |
| 图数据库（Neo4j） | 几百个节点在内存里就是个字典 |
| 多向量库 / 多 embedding provider 的抽象层 | 没有第二个使用场景 |
| 内容管理 UI（分类/标签增删改） | v1 的 `admin/categories`/`admin/tags` 6 个端点随之消失 |
| 展示 LLM 思考过程 | 已明确 |

## 本阶段新增决策（第 17-23 轮）

| # | 决策 | 影响 |
|---|---|---|
| 17 | **个人状态页 = 知识点掌握度矩阵**（不是日历热力图）；它与**面试报告**共用同一套聚合 | 后端聚合设计一次、两处复用；知识地图因此有了唯一可视化形式 |
| 18 | **面试报告由数据拼装**，只有一段总结由 LLM 生成（ADR-0003） | 报告可复现、可测试、不会与逐题评语矛盾 |
| 19 | **两层会话结构**：面试 → 题会话 → 作答；三种形态 = 同一结构的三组参数 | 数据模型骨架 |
| 20 | 公共题库只保留 **knowledge / design** 两类；**项目深挖题只存在于私有题集** | 公共题都有可客观评判的标准 |
| 21 | 注销 = **硬删身份与原文，保留聚合判定**（合规依据是「用户要求删除」，**不声称匿名化**） | 数据模型删改语义 |
| 22 | 知识点与岗位**多对多复用**；前置依赖在岗位内定义 | 掌握度跨岗位一致，不会分裂 |
| 23 | 三项都做：**导出我的数据 / 中途退出继续 / 最小观测** | 观测是三项里最重要的一项 |
| 24 | 题目与知识点**多对多**：主知识点（1 个，只管挂载与自修复）+ 关联知识点（0..N，用于组卷与覆盖检查）；**掌握度只由考察点命中记录推导** | 修正了一处系统性偏差：综合题牵动的知识点原本会被长期低估 |
| 25 | **编排层可在面试过程中调整后续题目**（跳过下游 / 插入前置，各有硬上限）——这是「维护对候选人的判断」的落地形式，但它不是一个独立的能力模型，而是编排层读本场判定结果 | 补上了 ADR-0001 早期遗漏的一半；面试因此不是固定题单 |

## 掌握度的定义（第 24 轮的结论，重要）

```
掌握度矩阵的每一格 = 该知识点下「被考过的考察点」里，候选人答到了多少
                    （不是分数，也不是题量）

它只依赖 hits（逐轮产出），与「这道题挂在知识地图的哪个节点下」无关。
```

三条推论：

1. **「没考过」是空格，「考了但没答」是 0%** —— 两者对候选人的含义完全不同，必须可区分。这要求命中记录在用户完全没答时也要记未命中，而不是只在答到时才有数据。
2. **一道综合题会同时填充多个格子** —— 库里真题 1065（设计一个可靠的 Agent 系统，要求支持幂等/熔断/限流/成本/权限/可观测）一道题就能在六个知识点上留下记录。
3. **不需要给「题目 ↔ 知识点」的关联加权** —— 权重问题被「格子装命中率而非分数」消解掉了。

## 验收标准（待定，草案）

- [ ] 三种形态都能完整跑通，共享同一面试官
- [ ] 额度点扣减准确；耗尽后题库可用
- [ ] 3009 道种子题已按知识点归位，且挂载错误可被答题数据自动发现
- [ ] 一道综合题能同时更新多个知识点的掌握度（用真题 1065 验证）
- [ ] 「没考过」与「考了但没答」在矩阵上可区分
- [ ] 流式输出中断时数据不丢（开始写/结束写/中断写三段式）
- [ ] 无进程内无界状态；无 async 上下文中的同步 DB 查询
- [ ] 所有降级都有用户可见状态 + 可查询记录（不静默）
- [ ] TLS 在部署文档中被列为前置条件而非待办
- [ ] `v1行为规格.md` 第 11 节的每个数字都有对应的实验脚本与结论
