## 1. 项目一句话

个人求职准备工具：每日自动采集面经 → LLM 出题 → 深挖追问链答题 → 四维判分 → 薄弱点复习，全本地运行（FastAPI + SQLite + bge-m3 本地向量）。

## 2. 运行方式

```bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000   # 启动服务
uv run pytest                                              # 289 个离线测试
uv run python -m app import 面经.md --type manual          # CLI 导入
uv run python scripts/bootstrap_generate.py                # 批量清理积压源（一次性）
uv run python scripts/migrate_tags.py                      # 旧题标签 LLM 重打（一次性）
uv run python scripts/migrate_difficulty.py                # 存量难度 LLM 重标 1-5（一次性，约 20-40 分钟）
uv run python scripts/polish_questions.py                  # 题库清洗（LLM 分类 keep/rewrite/delete，可复跑）
uv run python scripts/eval_retrieval.py                    # 检索评估（hit_rate/MRR）
```

- GPU torch 已装（2.6.0+cu124，requirements.lock 已 pin）；`.env` 需配 `LLM_API_KEY` + `NOWCODER_COOKIE`
- 浏览器用前 **Ctrl+F5 强刷**（前端静态文件可能被缓存）
- 数据备份在 Web 上传页（导出 zip / 导入恢复，导入前自动备份当前库）；PDF/DOCX/DOC 上传解析需系统 LibreOffice + mineru 模型（均已装，模型缓存 ~1.2GB 在 HF cache）

## 7. 给接手 agent 的提示

- 项目原则见 `AGENTS.md`（Karpathy 准则：先想后写、简洁、surgical、可追溯）
- 改动后必跑 `uv run pytest`；改前端后 `node --check app/web/static/app.js`
- 数据库迁移都在 `app/db.py` 的 `_migrate_*`（启动自动执行，幂等）；`init_db` 重建会先 dispose 旧引擎（备份导入依赖，Windows 文件锁）
- 涉及 LLM 的测试全部用 `tests/fakes.py` 的 Fake 实现，勿在测试中触网
- 文档解析链路：`app/parsers.py` 走 MinerU CLI（模型缓存 ~1.2GB）+ LibreOffice（系统安装）；测试用 monkeypatch `extract_text` 避免真调
- 大功能先做独立 demo（如 `demos/parse_demo.py`）人工审查后再集成（用户要求的工作流）
