# 生成超长截断修复 + 分批生成 实施方案

> 状态：已确认，实施中 ｜ 日期：2026-08-08

## 1. 根因

`LLMClient.complete()` 未设置 max_tokens → 模型默认输出上限（DeepSeek 4096 token）→ 长素材一次生成 30+ 题时 JSON 输出被截断（"Unterminated string at char 18582"）→ 解析失败 → 源 0 题。source #42/#26 偶发失败同款。

## 2. 修复

### M3 `llm_client.py`

`complete()` 支持 `max_tokens` 参数，默认 8192（DeepSeek 支持上限）。

### M8 `generate.py`

`generate_from_source` 按轮次分批生成：
- 复用 M4 `split_rounds(cleaned_text)` → 逐轮单独调 LLM（每轮注入完整 existing）→ 合并统一校验
- 无轮次结构（1 个 round）行为不变
- 单次输出规模 = 一章量级，告别截断

### 素材

章节标题去 `## ` 前缀（"一面：缓存与 Redis"…"八面：Spring"），8 章自然拆 8 轮。

## 3. 测试影响

| 文件 | 改动 |
|---|---|
| test_generate | 多轮素材 FakeLLM 响应序列逐轮；新增分批调用次数断言 |
| test_daily | 单轮素材不受影响 |
| test_llm_client | max_tokens 透传断言 |
