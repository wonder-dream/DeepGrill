# 用户上传题目（上传页：题目列表 / 面经文本 / 简历）实施方案

> 状态：已实施 ｜ 日期：2026-08-09

## 1. 前端：上传页 `#view-upload`

- 侧边栏「上传题目」→ `show("upload")`（替代原「点按钮弹文件窗口」）
- 页面：标题 + **三个方式切换按钮**（题目列表 / 面经文本 / 简历，各自描述文案）+ 文件选择（显示文件名/大小）+ 数量调节（仅简历，1-10 默认 5）+ 上传按钮 + 结果区（页面内展示，不用 alert）
- **题目列表**：上传 → `type=direct` →「已入库 N 题」+「去题库查看」
- **面经文本**：上传 → `type=facejing` →「已提交，后台生成中…」
- **简历**：上传 → `type=resume&count=` →「解析中…」轮询 `GET /api/upload/candidates/{token}`（每 3s，最长 6 分钟）→ **候选列表展示**（每题题干 textarea 可编辑校对，tags/难度只读 badge）→「确认入库」→ `POST /api/upload/confirm`
- **文件格式**：`.md/.txt/.pdf/.doc/.docx`；文本文件走 `content` 字段，**二进制文件走 `content_base64`**（前端 base64 编码）；响应 `mode=parsing` 时轮询 `GET /api/upload/status/{token}`（解析完成自动继续走对应模式流程，resume 完成带 candidates_token 续候选流程）

## 2. 后端

- `POST /api/upload` 加 `type`（direct/facejing/resume；缺省 auto 自动识别，兼容旧调用）；resume 分支 count 钳制 1-10；**大小限制 20MB**（文本 content / 二进制 content_base64 解码后校验）
- **二进制（pdf/docx/doc）**：返回 `{mode:"parsing", token}` → 后台线程 `extract_text`（app/parsers.py：MinerU CLI 解析 PDF/DOCX，LibreOffice 转换 DOC，见 docs/文档解析集成方案.md）→ 解析后按 type 继续走现有流程；`GET /api/upload/status/{token}` 轮询解析状态
- **简历流程**：写 `data/uploads/resume_{hash}.md`（importer 文件名前缀识别 resume 源）→ 后台线程 `generate_project_questions(source, count)` → 候选存内存 `_resume_candidates[token]`（线程锁，重启丢失可接受）
- `GET /api/upload/candidates/{token}`：解析状态 running/done/failed + 候选列表
- `POST /api/upload/confirm`：用户编辑后的题 → 校验 → 构造 project 题（默认 criteria）→ 与库内 embedding 去重（dedup）→ 后台入库；dedup 为既有语义（仅对库内旧题，批内不去重）
