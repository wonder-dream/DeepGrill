## 2. 部署方案（服务器执行，随下次部署一起）

### 2.1 TLS（nginx 终止，公网 https）

现状：容器直通宿主 8000，全链路明文（token/整库导出可被抓包）。

```bash
# 服务器（Workbench）：安装 nginx + certbot（域名需先解析到 <服务器IP>）
apt-get install -y nginx certbot python3-certbot-nginx

# /etc/nginx/sites-available/interview（示例，域名占位 YOUR_DOMAIN）
# server 块：监听 80 → 301 https；监听 443 ssl → proxy 127.0.0.1:8000
# 关键指令：
#   proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
#   client_max_body_size 100m;                                    # 上传/导入体量

certbot --nginx -d YOUR_DOMAIN     # 自动签发 + 续期
# 上 TLS 时需同步调整：compose 去掉 --no-proxy-headers（uvicorn 重新信任 XFF），
# 并把端口改为仅容器内部（127.0.0.1:8000:8000 或移除 8000 映射），
# 公网只经 nginx 443 进入 —— 否则攻击者仍可直连 8000 伪造 XFF 绕限流
```

- 部署后 nginx 统一 Server 头，uvicorn 只监听内网，公网不直接暴露 8000
- 无域名时可用云 LB 或 IP 直连自签证书（体验降级，不推荐）

### 2.2 owner 预置（防"首注册者=owner"抢注窗口）【已实现】

- 实现：启动时若库无 owner 且 `.env` 配置了 `OWNER_USERNAME`/`OWNER_PASSWORD` → 自动创建 owner（幂等，已有 owner 跳过）；未配置时回退现状（首注册者=owner）并 WARN
- 服务器 `.env` 追加：
  ```
  OWNER_USERNAME=localowner
  OWNER_PASSWORD=<强密码>
  ```
- 用途：新库/重建/导入覆盖后首次启动即锁定 owner，杜绝空库期间被抢注
