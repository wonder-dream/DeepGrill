# 题库清洗与自然化改写 实施方案

> 状态：已实施 ｜ 日期：2026-08-09
> 背景：题库存在面试者反问（"贵公司主要做什么业务"）、闲聊/流程题（"还有什么想问的"）等非技术题，以及口语化/含糊/一题多问的不自然表述

## 1. 脚本 `scripts/polish_questions.py`（一次性，可复跑，后台运行）

### 阶段 1：全量分类（2225 题逐题 LLM）

- prompt 三类判定：`delete`（反问/闲聊/流程/无关主观话题）/ `rewrite`（技术考点但表述不自然）/ `keep`
- 分类失败**保守记 keep**（不误删）；每 20 题进度日志

### 阶段 2：删除（delete 类）

- 先导出备份 `data/backup/polish_deleted_<时间戳>.json`（id+stem，可追溯）
- 级联删除：ORM 删 sessions（cascade 删 attempts/judgments）→ 删 question（FK 安全）

### 阶段 3：改写（rewrite 类）

- LLM 改写约束：保持原语义与考点 / 统一"请解释/请描述/请设计/为什么"句式 / 一问一题不拆不合 / 去口语化
- 校验：非空、长度 ≥6、与库内现有题干去重；type/tags/difficulty/criteria 不动（语义保留故仍适用）
- 失败/无效跳过记日志

## 2. 生成侧防再犯（`app/pipeline/generate.py`）

- GENERATE_PROMPT 第 5 条补「面试者反问（如'贵公司主要做什么业务''还有什么想问的'）」显式排除
- 两个 prompt 第 2 条补句式约束：「stem 必须是自然完整的面试问句（请解释/请描述/请设计/为什么…句式），禁止口语化、禁止一题多问」

## 2.5 输入时处理（2026-08-09，上传直接模式）

- 直接模式后台任务 `_tag_direct_questions` 一次调用同时输出 `{stem, tags, difficulty, verdict: keep|rewrite|delete, new_stem}`：
  - `delete`（反问/闲聊/流程题）→ 后台级联删除
  - `rewrite` → 用 new_stem 更新题干（保持语义自然化）
  - `keep` → 仅补标签/难度；verdict 缺省按 keep（失败不误删）
- 上传立即返回「已入库 N 题」，后台数秒内完成校验（先入后清，与补标签同模式）

## 3. 运行与进度

- `uv run python scripts/polish_questions.py`（后台进程，日志 `data/logs/` 或控制台重定向）
- 预计 25-40 分钟（2225 分类 + 数百改写，DeepSeek 生成模型）
- 进度查询：读日志尾部 / 查库计数

## 4. 验证

- 清理后反问/闲聊关键词残留计数趋近 0
- 抽查改写样本句式自然度
- 结果（删 N / 改 M / 失败）记录入 docs/修复记录.md
