# 部署在境外单机，Cloudflare 做 CDN 与访客 TLS，源站保持可移植

> 状态：accepted ｜ 影响文档：`docs/v2范围基线.md`（部署与基础设施）· `AGENTS.md` §四 ｜ 补记：原只写在基线里，无对应 ADR

目标机器是**境外（美东弗吉尼亚）单机 2C2G（上限 4C8G）**，因为阿里云按量实例无法备案。网络层用 **Cloudflare 免费版**做 CDN、隐藏源站与访客侧 TLS；**源站保持可移植**（Caddy 同时具备直连 Let's Encrypt 的能力，CF 不可达时只需改 DNS）；源站证书优先用 **Cloudflare Origin Certificate**（免 ACME、长有效期，消除证书续期这个静默故障源）。存储用 **SQLite + WAL**（调低页缓存），备份定时到对象存储。

## 为什么需要这份 ADR

这份决策原本只写在 `docs/v2范围基线.md` 里，没有对应的 ADR。而它满足 ADR 的全部三条判据：**难反悔**（换机房、换 CDN、换证书策略都是大动作）、**未来读者会奇怪**（"为什么服务器在美国东部？"）、**有真实备选**（国内服务器、隧道、其他云）。补记于此。

## 这个约束反推出的硬要求

**2C2G 不是随便选的数字 —— 它否掉了一个 v1 的部署前提：**

| 要求 | 来源 |
|---|---|
| **嵌入必须走 API** | 本地 bge-m3 需约 2.3GB 常驻内存，在 2C2G 上根本起不来。v1 的部署方式在这台机器上不成立 |
| **禁止全量加载大表** | v1 的「全表 embedding 拉成矩阵（每请求 O(N) 内存）」在 2G 上是定时炸弹 |
| 静态资源强缓存 + 压缩 | 境内直连美东的往返延迟量级见 `docs/v2范围基线.md`（部署与基础设施）；SSE 每 token 跨境一个来回 |
| **迁移与启动分离** | 单机 + 无备份窗口 → 启动时静默删数据的迁移（v1 的 `_migrate_users_email`）不可接受 |
| 备份**必须验证能恢复** | 数据库与机器同生共死，是当前最大单点风险（v1 发生过一次整库覆盖冲掉 users —— 见 `docs/v1现状-20260913.md`） |

**网络路径是隐藏的硬约束**：服务器在美东、用户在境内 —— 若将来做语音（实时双向流），大概率需要**客户端直连语音服务**（绕过应用服务器）。详见 `docs/v2范围基线.md` 的「已评估但暂缓」。

## Considered Options

- **国内服务器 + 备案**：延迟最好，但按量实例无法备案 → 只有包年包月可选，前期成本与流程都不合适。
- **不用 CDN，源站直连 + Let's Encrypt**：最少依赖、以后搬国内零改动，代价是境内访问慢、源站 IP 暴露。
- **全量绑定 Cloudflare（含 R2 做备份）**：最省事，代价是深度绑定 —— CF 不可达时你与用户都进不去。
- **Cloudflare Tunnel 而非直连**：隐藏源站、自带 TLS、不开入站端口，但多一个外部依赖，且国内访问 CF 同样不稳定。

## Consequences

- **"可移植"的代价极低**：它只意味着源站自己也能签证书，而这只是一段配置。换来的效果是 —— 那个"无法备案"的困境从**架构级约束**降级为**可替换选项**。
- **Cloudflare 免费版可以长期用，但不能把架构绑死在它上面**：免费版没有中国大陆节点，SLA 不保证，国内可达性会波动。
- **备份与 CDN 是两件独立的事**：CDN 解决"外面进得来"，不解决"里面丢了就没了"。
- **本决策不覆盖备份与观测的具体做法**（频率、保留策略、恢复演练、告警渠道）—— 待定。
