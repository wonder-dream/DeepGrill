# 面试官是一个 workflow（带循环的状态机），而不是自主 Agent

面试官由两层构成：**编排层**（代码持有全部硬约束 —— 问哪几道题、每题追问轮数上限、何时必须收尾）与**单一引擎**（一个无状态能力：输入题目、对话历史与本轮回答，输出追问、收尾或评分）。**单题范围内面试官自主**，自己判断这一句答得含不含糊、还要不要往下挖；追问的驱动不来自题目的预设难度，而来自「探到这个候选人在这个知识点上的能力边界」。

## 它属于哪一类 workflow

按 Anthropic 在 [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) 里的划分：**workflow** 是「LLM 与工具通过预定义的代码路径被编排」，**agent** 是「LLM 动态决定自己的流程与工具使用」。本项目的控制流（提问 → 等待 → 判分 → 继续或收尾）由**代码**决定，模型只在节点内做局部决策 —— 因此它是 workflow，不是 agent。中文业界进一步区分「Agentic Workflow」（工作流里嵌 LLM 决策节点）与「Agent based on Workflow」（Agent 去调工作流），本项目属于前者。

在 workflow 的模式分类里，它最接近 **evaluator-optimizer 的变体**：每一轮把「候选人回答 + 对话历史」交给同一个引擎，引擎同时产出 ① 本轮评估 ② 下一步决策；代码拿到决策后执行状态转移，**并在硬上限处行使否决权**（LLM 可以建议收尾，但 `max_rounds` 到顶时代码强制收尾）。**否决权归属就是 workflow 与 agent 的分界线。**

⚠️ **但它不是线性 workflow，而是带循环的状态机。** 同一道题内要循环追问、候选人可中途退出后恢复、答得差则强制收尾而答得好则加深、一题结束后进入下一题的同类循环。任何按静态 DAG 或固定步骤链来实现它的方案都会卡在「循环 + 挂起恢复」上。

## Considered Options

- **自主 Agent（工具循环）**：面试官在整场范围内自主选择问哪题、挖多深、何时结束。最像真面试官，但成本不可预测、行为难以验收，且本项目没有真实面试样本与预算做 A/B 调优。
- **多角色单元（出题官 / 追问官 / 控场官 / 评分官）**：各单元可独立调试，但 LLM 迁移时要重测 N 套 prompt，且角色交接处容易出现体验断层。
- **候选人模型驱动**：维护一份「我对这个人的判断」，提问、判分、复习全部由它派生。设计最深，但也最复杂，对单场面试属过度设计。

## Consequences

- **编排层在面试过程中可调整后续题目**：这是从路线 4 借来的「维护一份我对这个人的判断」的落地形式 —— 但它**不表现为一个独立的能力模型**，而是表现为**编排层读取本场已产生的判定结果**（哪道题、命中或漏掉了哪些知识点的哪些考察点），据此执行两个动作：**跳过**一道与刚失败的下游知识点相关的后续题，或**插入**一道前置知识点的题。两者都有硬上限（跳过 ≤ 计划题数的 1/3、插入 ≤ 2 道），且总题数不变 —— **「成本可预测」这条约束没有放松**。
  这样做的理由：① 判断留在代码里，不变成模型的自由裁量权（与本文的分界线一致）；② 用到的信号（逐题判定结果）是本来就要产出的，不是新机制；③ 避免了「能力判断」与既有的逐题判定、掌握度矩阵三者说同一件事。
  代价：① 两场面试的题目因此不完全相同，**不可逐题对比**（报告本来就按掌握度矩阵对比，不按题目）；② `interviews.plan` 从「固定题单」变为「固定题单 + 调整日志」。
- **追问深度评分必须重新设计**：v1 的 `depth` 分来自「答到了预设的第几层」（目标深度 = `min(5, difficulty+1)`），因为难度预设了目标层。现在追问深度由当场表现驱动，`depth` 只能改为「实际体现出了哪些深度」由判分直接评定。这是 v1 算法层里**唯一必须推倒重来**的一项。
- **换模型只重测一次**：单一引擎意味着 prompt 迁移成本是常数，这对下一次模型升级很重要。
- **面试官必须可拆装**：额度耗尽后题库仍需可用，因此引擎调用必须是可选的，不能把判分焊死在会话流程里。
- **状态必须显式落库**：流程不是一次调用就结束，中途要能挂起与恢复。这直接决定数据模型 —— `interviews.status`（active / finished / abandoned）、`sessions.status`、`attempts.round_no` 三者共同表达状态机当前所在的位置。
- **v1 也是一条 workflow**：v1 的追问链已经是「代码控轮数 + LLM 决定追问什么」的 workflow。本决策**保留了这个形态**，只换掉了追问的驱动逻辑（由题目难度改为能力边界）。因此这一步的改动量比看上去小 —— 改的是决策依据，不是架构形态。
