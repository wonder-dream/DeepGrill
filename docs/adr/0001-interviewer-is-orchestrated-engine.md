# 面试官由「编排层 + 单一引擎」构成，而不是自主 Agent 循环

面试官（提问 / 追问 / 判分）实现为一个无状态能力：输入题目、对话历史与本轮回答，输出追问、收尾或评分。**硬约束全部由编排层持有**——问几道题、每题追问轮数上限、总轮数上限、何时必须收尾；**单题范围内面试官自主**，自己决定这一句答得含不含糊、还要不要往下挖。追问的驱动不来自题目的预设难度，而来自「探到这个候选人在这个知识点上的能力边界」。

## Considered Options

- **自主 Agent（工具循环）**：面试官在整场范围内自主选择问哪题、挖多深、何时结束。最像真面试官，但成本不可预测、行为难以验收，且本项目没有真实面试样本与预算做 A/B 调优。
- **多角色单元（出题官/追问官/控场官/评分官）**：各单元可独立调试，但 LLM 迁移时要重测 N 套 prompt，且角色交接处容易出现体验断层。
- **候选人模型驱动**：维护一份「我对这个人的判断」，提问、判分、复习全部由它派生。设计最深，但也最复杂，对单场面试属过度设计。

## Consequences

- **追问深度评分必须重新设计**：v1 的 `depth` 分来自「答到了预设的第几层」（目标深度 = `min(5, difficulty+1)`），因为难度预设了目标层。现在追问深度由当场表现驱动，`depth` 只能改为「实际体现出了哪些深度」由判分直接评定。这是 v1 算法层里**唯一必须推倒重来**的一项。
- **换模型只重测一次**：单一引擎意味着 prompt 迁移成本是常数，这对下一次模型升级很重要。
- **面试官必须可拆装**：额度耗尽后题库仍需可用，因此引擎调用必须是可选的，不能把判分焊死在会话流程里。
