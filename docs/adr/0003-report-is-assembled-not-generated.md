# 面试报告由数据拼装，只有一段总结由 LLM 生成

> 状态：accepted ｜ 影响文档：`docs/v2数据模型.md`（interviews.report_body / report_summary · report_items）· `CONTEXT.md`（面试报告）· `docs/v2范围基线.md` 决策 27 · `AGENTS.md` §四 ｜ 实现后补记：**总结的 grounding 检查从"闸门"改成"信号"**（四次误报，见文末补记）· 兜底文案改为"组装式"（三路线对比后的选择）

一场**模拟面试**结束后的报告，其主体（总分、四维分、掌握度矩阵的变化、逐题回顾、该补的前置知识点、主要问题清单）全部由**已经产生并落库的数据**查表或运算得到；只有最后一段「这场面试说明了什么」的自然语言总结由 LLM 生成。

## 报告由哪六块组成，各自来自哪里

```
① 总分 + 四维分 ──────── 【查】 evaluations.total_score / scores
② 掌握度矩阵变化 ─────── 【算】 「本场之前」与「本场之后」的命中率相减
③ 逐题回顾 ──────────── 【查】 report_items 的快照 + evaluations + attempts
④ 该补的前置知识点 ───── 【图】 沿 knowledge_point_edges 往前置方向走一跳
⑤ 主要问题清单 ───────── 【算】 漏得最多的考察点，按知识点归类
⑥ 一段总结 ←─────────── 【唯一的 LLM】
```

**③ 是报告的主体，它的每一行在面试过程中就已经产生了**：

```
第 3 题 · 知识点「volatile」· 45 分
  题目 / 考察点 / 评分标准          ← report_items 的快照（生成时冻结）
  你的回答                        ← attempts.answer_text
  面试官评语                      ← evaluations.review
  判定（① 半对 ② 未命中 ③ 未命中）  ← attempts.hits（末轮快照）
```

**只有 ②④⑤ 需要计算，且都不调 LLM** —— ②⑤ 是聚合，④ 是沿**前置依赖边**走一跳（「volatile 的考察点②没答到」→ 查前置边 → 「建议先补 JMM 内存模型」）。

## 那段总结收到什么、收不到什么

**输入**（全部是已算出的结论）：四维分与总分、命中率最高与最低的知识点、漏得最多的考察点、前置缺口（④）、**逐轮命中轨迹**（"第 1 轮命中 ①、第 2 轮命中 ②、第 3 轮 ③ 始终未命中"）。

**明确不输入**：

| 不输入 | 为什么 |
|---|---|
| **完整对话记录** | 判分器已经读过一遍。再让它读一遍等于**重新判断一次** —— 幻觉的主要入口 |
| 逐题评语改写任务 | 评语已经写好，重写只会产生措辞不一致 |
| 「再评估一次这个人的能力」 | 会与逐题判定、掌握度矩阵**三者说同一件事**，开始漂移 |

**总结的角色是「把已算出的结论综合成一段人话」—— 它是朗读者，不是裁判。**

## 硬约束：总结里不许出现数据里没有的东西

> ⚠️ **本节在实现后被修订过一次（见文末「补记」）**：约束本身不变，但**它实现成了
> 信号而不是闸门** —— 原文那句"这条可程序化检查（跑一次字符串匹配即可）"过于乐观，
> 实测四次误报、每次都在丢正确输出。理由与证据在补记里。

总结提到的每个知识点名，都必须能在 ② 或 ④ 的结果里找到。

因此报告这一段是 v2 里**少数可以写确定性测试的 LLM 相关环节** —— 输入固定、约束可验证。

## 生成时机：finish 时全部算好并落库

报告主体与总结**都在面试结束时计算并持久化**：

- **主体必须在 finish 时算** —— ② 依赖「本场之前」这个时间点，事后重算可能与当时不同
- **总结也必须存库** —— 否则每次打开措辞都会变，与「报告不重新生成」矛盾

## Considered Options

- **LLM 通读整场对话后自由生成报告**（v1 的 `review_paper` 思路）：文字更自然，但会把已经算出来的判断重新猜一遍，是幻觉的主要入口；且**可能与逐题评语矛盾**（某题判定「没答到内存屏障」，总结却写「并发基础扎实」）——这种矛盾用户很难发现，但会直接摧毁信任。
- **极简报告**（只给分数 + 矩阵变化 + 前置建议）：成本最低，但丢掉了逐题回顾这一最有价值的复盘材料。
- **不落库、每次打开现算**：存储最省，但报告会随题库编辑而变动，且每次打开都要重付一次 LLM 调用。

## Consequences

- **逐轮判断是唯一的判断来源**：每道题的考察点命中情况必须在面试**进行中**就判定并落库，不能推到报告生成时。这反过来要求面试官每轮都要输出「答到了哪几条考察点」。
- **报告可以部分生成**：用户中途退出也能看到已完成部分的报告，因为数据是按轮次累积的。
- **报告可复现**：同一场面试的报告是确定性的，不含随机性，因而可被测试断言。
- **「个人状态页」与「面试报告」共用同一套聚合**：前者是历史全量、后者是本场增量，视图不同但数据来源相同。
- **`report_items` 不设「每题一段总结」字段**：逐题评语就是 `evaluations.review`，不重复生成。
- 用户可见的报告文字因此**偏结构化、偏克制**。这是有意的取舍：宁可像体检报告，不要像散文。

## 补记（实现后，真调模型才暴露）

### ① "字符串匹配即可"是错的：这条检查按词法做不出来

原定"每个知识点名都要能在 ② 或 ④ 的结果里找到"并实现成**准入检查**（不通过就丢弃
总结、降级为确定性文案）。配上真模型之后，它连续**四次误报**，每次都在丢正确输出：

| 误报的东西 | 它其实是 |
|---|---|
| 汉字 2-4 字片段 | 正常句子本身（「这场面试说明…」的每个片段都被判成编造） |
| 标题类文本 | 规则本该跳过的东西 |
| `synchronized` | **考察点正文里**的技术名词（"与 synchronized 的适用场景区别"） |
| `accuracy` / `completeness` 等 | **报告自己的**四维分维度名 |

四次指向同一件事：**"总结里的每个词是否在数据里"这件事，词法匹配做不到** —— 因为
"总结"这项任务的本质就是改写与归纳，而精确匹配必然漏检、子串/相似度匹配必然误报，
中间的阈值没有正确取值（它属于 §未决 6 那一类要靠实验标定的参数）。

**所以改为信号**：模型写的总结一律保留，疑似数据外的名词记进
`interviews.report_body.ungrounded_terms`，页面据此标注一句"请以逐题回顾为准"。

### ② ADR 真正担心的那条，现在**部分**被守住了

本文开头列的三条"不输入"里，最要紧的是**防止与逐题评语矛盾**（"某题判定没答到内存屏障，
总结却写并发基础扎实"）。补记①之后这条一度完全没人守；现在由
`app/report/service.py::check_summary()` 守住**可判定的那部分**：

| 断言类别 | 怎么验证 | 能否做到 |
|---|---|---|
| **数字必须来自数据**（含其函数，如四维合成的总分） | 数字是**闭集词汇**，逐个比对即可 | ✅ 精确 |
| **"哪一维最弱"必须与 `evaluations.scores` 一致** | 同一句里"维度别名 + 最弱措辞"→ 与各维均值比对 | ✅ 窄但可判定 |
| 中文编造的知识点名、跨句语义矛盾 | 需要名词表 + 相似度，或模型裁判 | ❌ 不在能力范围 |

关键区别：**数字与"哪维最弱"都是闭集**，所以词法比对在这里是**精确**的 ——
这与补记①里失败的"名词是否在数据里"（开放集）是两件不同的事。

它同样**只是信号**（页面标注、不阻断），并且带误报守卫测试。
附带能力：总结若报了一个与四维分对不上的总分，也会被当作未知数字抓出来。

### ③ 兜底形态选了"组装式"（三条路线对比过）

模型那次没成功时的文案，现在由 `_assemble_summary()` **按模板从已算出的结论里拼**
（点出最低的那一维、掌握度变化、最该补的那条），而不是原来那句只报总分的短句。

依据是一次三路线对比（同一份真实报告、同一模型）：组装式 / 受限生成 / 自由生成。
结论是**保留自由生成**（它的可读性最好、且忠实度检查三者全通过），
**否决受限生成**（它退化成罗列数据原文，还更贵），**把组装式用在兜底**上
—— 它从不编造、零 token、完全可复现，而"模型失败"恰恰是最不该再冒险的时刻。
