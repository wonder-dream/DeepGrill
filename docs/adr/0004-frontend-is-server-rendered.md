# 前端以服务端渲染为主，浏览器只负责一个页面

> 状态：accepted（取代本文件早期版本「零构建薄壳 + 客户端渲染」，同日重写并改名；面试页状态清单再按 **ADR-0009** 收窄 —— 不再有「转写确认/编辑中间态」）｜ 影响文档：`AGENTS.md` §四 · `docs/v2范围基线.md` 决策 34

列表、筛选、分页、掌握度矩阵、面试报告**全部由服务端渲染整页 HTML**：筛选与翻页靠 **URL 参数**（不是 JS 状态），表单用**原生 POST + 重定向（状态码 302）**（不是 fetch），事件用**委托**（整张表一个监听器，重画不需重绑）。

**浏览器里跑 JS 的只有一个页面：面试页** —— 它要做三件服务端无法替代的事：**SSE 流式接收**、**麦克风录音 + 语音转写**、**当前会话的轮次状态**。

不引入打包器与框架（原生 ES 模块 + JSDoc 类型注释即可）。

前提是 owner 不编写也不调试前端代码（由 AI 生成）——因此选型标准不是「写得省力」，而是**出错时的排查面**，以及**状态出错时会不会静默**。

## Considered Options

- **客户端渲染 + JSON API（单页应用式）**：前端 JS 把 JSON 画成 DOM，筛选与翻页是 JS 内部状态。它的代价不在"写得累"，而在**状态住在浏览器变量里** —— 而"筛选条件 + 页码 + 排序"这类状态最容易**静默出错**：不崩溃，只是显示错数据。对一个"前端不由 owner 编写与调试"的项目，这类错误会存活很久。
- **Vite + Vue / Svelte + TypeScript**：响应式天然适配对话界面。但多出「源码 → 构建 → 产物 → 浏览器」四层，构建配置本身即一类故障源；且依赖需持续升级。**这仍然是"状态住在浏览器"的方案**，因此上一条的问题它同样有。
- **纯服务端渲染 + 无 JS**：连流式对话也放弃 → 面试体验断崖式下降（用户要盯着空白等 10-30 秒）。否决。

## Consequences

- **前端的职责缩小到"一个页面"**：面试页之外没有前端应用要维护 —— 这是本决策最大的收益。
- **状态住在 URL 与服务端，而不是浏览器变量里**：浏览器前进/后退天然正确，刷新不丢筛选条件，而这些都是客户端渲染那条路里需要手写且极易出错的地方。
- **事件泄漏问题消失**：事件委托让"重画表格"不需要重新绑定监听器（v1 实测有上百个 `addEventListener` 而只移除了两个 —— 就是这个坑，数字见 `docs/v1现状-20260913.md` §前端痛点）。
- **排障只看一个地方**：HTML 由 Python 生成，页面出错就查 Python，不必跨 Python 与 JS 两个世界找。
- **API 风格随之确定**：**大部分路由返回 HTML**（服务端渲染），只有面试页提供 SSE 接口。以后若要纯数据 API（小程序 / App 客户端），需要**另开一组路由**，不是改造现有路由。
- **必须引入模板引擎与它的 XSS 纪律**：服务端拼 HTML 一样会中 XSS。v1 在复习卷那块用过白名单消毒（bleach），该经验可直接搬。
- **面试页成为唯一复杂的前端模块**，它要处理：SSE 流式渲染、录音与转写、当前轮次状态。**这是唯一需要认真测前端的页面。**
- **UI 形态被限定为「服务端页面 + 一个对话框」**：若未来出现「多个面板互相触发刷新」的控制台型界面，本决定需要重新评估。
- **先做静态原型再接入逻辑**：视觉用无 JS 的静态页面确认，再接数据与交互。避免「一改样式就碰坏功能」。
- **不做组件库**：观感由设计令牌（间距尺度、颜色变量、字号比例、统一圆角与阴影）与状态细节（加载/悬停/聚焦/禁用/空态/错误态）决定，而非由框架决定。弹窗与折叠面板优先用原生 `<dialog>` / `<details>`，连手写组件都不需要。
