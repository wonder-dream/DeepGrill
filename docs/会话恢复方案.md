# 追问中会话恢复接线（D18 落地）实施方案

> 状态：已确认，实施中 ｜ 日期：2026-08-08
> 对应 DESIGN D18「中断会话恢复」——设计早已存在，前端从未接线

## 1. 问题

追问中（active）会话刷新后"丢失"：`POST /api/sessions` 不检查已有 active 会话，前端 `startAnswer` 永远新建会话、从不调用 resume——上一轮问答不可见，实为恢复流程断裂（数据都在 attempts 表）。

## 2. 修复

### 后端 `POST /api/sessions`

该题已有 active 会话 → 直接返回它（`{"session_id", "status": "active", "resumed": True}`），不重复创建；无则正常新建。

### 前端 `app.js`

- `startAnswer(q)`：`q.active_session_id` 存在则直接复用（resume），否则 POST 创建
- 复用/已有轮次时：GET `/api/sessions/{id}`（active 状态含 transcript）→ `renderChat(transcript)` 恢复时间线（含 L 徽标）→ 输入框清空继续答
- 今日列表 badge：`active_session_id && !done` → "进行中"徽标

### 测试

- 已有 active 会话再创建 → 返回同一 session_id + resumed=true，sessions 数量不变
- 无 active → 正常新建

## 3. 文档

- docs/修复记录.md 记录；DESIGN D18 标记前端入口落地

## 4. 验证

`uv run pytest` 全绿；重启 + 强刷后：答一轮 → 刷新 → 点"进行中"卡片 → 时间线恢复、继续作答。
