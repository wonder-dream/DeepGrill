### 修复 1：非 UTF-8 编码 config.yaml 漏出原始异常（🟡 #1）

- 位置：`app/config.py` `load_config`
- 问题：GBK/UTF-16 BOM 编码时 `read_text(encoding="utf-8")` 抛 `UnicodeDecodeError`（ValueError 子类），不在 `FileNotFoundError`/`OSError` 捕获范围内，原始异常直接泄漏，违反"全部配置错误归为 ConfigError"契约
- 修复：新增 `except UnicodeDecodeError` → `ConfigError("config file must be utf-8 encoded: {path}")`，保留 `from e` 异常链
- 复现测试（先写后修）：`tests/test_config.py::test_non_utf8_encoding_raises_config_error` —— 写 GBK 字节，断言 `ConfigError` 且消息含 "utf-8"

### 修复 2：precedence 测试断言无意义（🟡 #2）

- 位置：`tests/test_config.py::test_environment_variable_takes_precedence_over_dotenv`
- 问题：`assert True` 不验证任何行为；配置对象只存变量名，原测试无法观测优先级结果
- 修复：load 后断言 `os.environ` 中两变量仍为 env 注入值（`sk-from-env` / `cookie-from-env`）——若 dotenv 覆盖生效该断言即失败

### 修复 3：dotenv 测试可绕过 .env 通过（🟡 #3）

- 位置：`tests/test_config.py::test_secrets_read_from_dotenv_file`
- 问题：开发机若全局已设同名环境变量，.env 未被咨询测试也通过，无法证明 .env 加载生效
- 修复：测试内先 `monkeypatch.delenv` 两变量（`raising=False`），加载后正向断言值来自 .env（`sk-from-dotenv`）——值只能来自 .env 路径
