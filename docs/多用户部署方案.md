# 多用户化改造与公网部署（阶段 A 已完成 / 阶段 B 已完成）实施方案

> 状态：阶段 A/B 已实施 ｜ 日期：2026-08-09
> 决策：开放注册至 20 人（不含 owner）；公共题库共享；Docker 部署；弗吉尼亚节点（免备案）；4C8G 经济型 e

## 1. 数据模型（A1）

- `users`：username(唯一)/password_hash(scrypt)/role(owner|user)/created_at；**首个注册用户 = owner**
- `user_tokens`：token_hash(sha256)/user_id——可撤销、重启不掉线（零依赖，不用 JWT）
- `user_picks`：user_id/question_id/picked_at——每用户今日选题（替代 Question.status=today 全局语义，按天自然隔离）
- `sessions.user_id` 列（幂等迁移 `_migrate_session_user`）；SQLite 开 **WAL**（多用户并发读写）
- 旧单用户数据回填：首个用户注册时 `backfill_owner_data`（sessions 归 owner + 今日题转 picks）

## 2. 认证（A2）

- 密码：`hashlib.scrypt`（标准库），存储 `scrypt$salt$hash`；**≥8 位字母+数字混合**（正则校验）
- 接口：`POST /api/auth/register`（名额 COUNT(role=user) ≥ 20 → 409「名额已满」）/ `login` / `logout` / `GET /api/auth/me`
- 鉴权依赖：`require_user`（Bearer token，无效 401）、`require_owner`（403）
- 前端：登录/注册视图（首个注册提示管理员）、401 自动跳登录；token 经 HttpOnly Cookie 自动携带，JS 不再读写 localStorage

## 3. 数据隔离（A3）

- 题库共享（bank/review 题目部分）；**done 标志按用户**（`_latest_judgment_by_question(user_id)`）
- per-user：今日列表/日历回看（user_picks）、会话创建/答题/判分/轮询/恢复/删除（越权 404）、历史（按用户 picks 分组）、weak_tags 聚合、复习卷缓存（key=user:tag）
- **上传/备份/流水线/题库管理仅 owner**（require_owner，普通用户 403）

## 4. 今日选题（A4，懒加载）

- 用户打开今日页时：今天无 picks → 按 D8 配额（knowledge 3/design 2/project 1）从公共 pending 池选题
- 昨日未完成题不展示（按天隔离），今天重新进入待选池；无需显式回收逻辑
- 全局流水线照旧维护公共题库（owner 触发）

## 5. 管理员题库管理（A7）

- `PUT /api/admin/questions/{id}`：stem/tags/difficulty/good/bad criteria 可改（type 不可改）
- `DELETE /api/admin/questions/{id}`：级联删会话/判分/用户 picks（FK 安全）
- 前端：题库页 owner 每卡「编辑/删除」，编辑弹层表单

## 6. 测试（+14）

- auth：首用户 owner/重复 409/弱密码 400/名额满 409/登录/登出失效/未登录 401
- 隔离：跨用户会话 404、done 按用户、今日 picks 独立
- 管理：owner 编辑/删除、普通用户 403
- 全量回归 **303 passed**（现有测试 make_client 自动建测试用户 + token）

## 7. 阶段 B（部署，已完成）

- Dockerfile（python:3.13-slim + uv + CPU torch + MinerU 模型预下载 + LibreOffice）；docker-compose（app + 数据卷 + env）
- Linux 适配：`parsers.py` SOFFICE 候选路径加 `/usr/bin/soffice`
- nginx/caddy HTTPS（可选域名）+ 自动备份 cron（HTTPS 未做；备份见下）
- 环境变量：LLM_API_KEY / MAX_USERS / ADMIN 相关；**生产/公开不配置 NOWCODER_COOKIE**（牛客源仅本地个人学习，`sources.nowcoder_enabled` 默认 false）
- **实际部署**：容器 `interview-assistant` 于 0.0.0.0:8000 运行（Ubuntu 24.04, 4C8G 弗吉尼亚）；**SSH 公网被阿里云云盾拦截** → 运维通道用 Workbench 网页终端 + 文件上传；浏览器 http://<服务器IP>:8000 注册首个 owner 成功

## 8. 明确不做

- 每用户独立题库（成本×20）；邮箱验证/找回密码；JWT（DB token 足够）；角色细分（owner/user 两级够用）

## 10. 安全加固：登录/注册速率限制

- `app/ratelimit.py`：内存滑动窗口（IP 维度，零依赖），`check/fail/success/reset`
- `app/web/routes.py`：`auth_rate_limit_middleware` 仅拦 `/api/auth/login` `/api/auth/register`
- 规则：同一 IP 60s 内失败（响应 ≥400）≥5 次 → 429「尝试过于频繁」；成功响应清零计数；内存态重启失效（单进程可接受）
- 测试：test_auth.py 3 用例（登录 429 / 成功清零 / 注册 429）；conftest 每测试 reset 防跨测试污染

## 9. 本地题库迁移到服务器（方案，待执行）

> 状态：已部署（弗吉尼亚 <服务器IP>），本地继续优化后再执行迁移
> 背景：服务器为新空库（无题库），本地库 2293 题 + embedding 需迁移；服务器已注册 owner 用户

### 方案：整库备份 zip + 定向迁移（只搬题库层）

**为什么不用 Web「导入备份」**：导入是整库覆盖——会冲掉服务器已注册的 users/user_tokens/user_picks（owner 账号）。改为定向迁移脚本，只复制公共题库层。

### 步骤

1. **本地导出**：本机 http://127.0.0.1:8000 → 上传页 → 数据备份 → 导出备份（zip，含 sources/questions/embedding/判分）
2. **上传 zip**：Workbench 上传 `interview_backup_*.zip` 到服务器（如 /root/）
3. **迁移脚本**（一次性 `scripts/migrate_questions_from_backup.py`，服务器容器内跑）：
   - 读 zip 中 interview.db（sqlite3 标准库，不动 ORM）
   - 复制 `sources` + `questions` 全行（**保留 id 与 embedding BLOB**，2293 题向量免重算）到服务器库 `/app/data/interview.db`
   - 可选：本地 `sessions/attempts/judgments`（若本地有判分数据）映射到服务器 owner 用户 id
   - **不碰** `users` / `user_tokens` / `user_picks`
   - 幂等：可先删后插或跳过已存在 id
4. **验证**：`SELECT COUNT(*) FROM questions` = 2293；页面刷新题库可见

### 注意

- 服务器库路径：容器内 `/app/data/interview.db`（挂载卷 ./data，改前备份）
- 迁移在容器内执行（`docker compose exec app python scripts/...`）或宿主 sqlite3 直接操作挂载卷文件
- 本地继续优化产生的题，迁移前重新导出最新 zip 即可
