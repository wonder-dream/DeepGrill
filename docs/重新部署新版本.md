# 重新部署新版本（日常迭代升级）

> 适用：已有服务器实例（Ubuntu 24.04，`/opt/interview-assistant`，Docker Compose）上的**增量代码更新**
> 首次从零部署见《服务器部署方案.md》；备份/运维见《服务器运维清单.md》
> 核心原则：**代码可覆盖，数据（`./data`）与 `.env` 不可丢**——打包与解压时严格按下面的步骤

## 1. 本地打包（Windows / PowerShell）

在项目根目录执行：

```powershell
tar -czf deploy_package.tar.gz --exclude=.git --exclude=.venv --exclude=data --exclude=backups --exclude=deploy_package.tar.gz --exclude="interview_backup_*.zip" --exclude="__pycache__" --exclude="*.pyc" --exclude=.env --exclude=.pytest_cache --exclude=.idea --exclude=.opencode .
```

**必须排除 `.env`**（真实 API key + 牛客 cookie 不得进部署包）与 `data`（服务器上的题库/用户数据不能被打包覆盖）。打包后验证无敏感文件：

```powershell
tar -tzf deploy_package.tar.gz | Select-String "env$|\.env|interview\.db"
# 期望：无输出（只有 .env.example 可保留）
```

## 2. 服务器更新（Workbench）

1. **上传** `deploy_package.tar.gz` 到服务器 `/root/`
2. 依次执行：

```bash
cd /opt/interview-assistant
# 2.1 备份当前 .env（新包不含它，防手滑）
cp .env /root/.env.bak
# 2.2 解压覆盖代码（data/ 已从包中排除，题库数据不受影响）
tar -xzf /root/deploy_package.tar.gz
# 2.3 恢复 .env
cp /root/.env.bak .env
# 2.4 重新构建并启动（仅依赖变化时才需要 build；纯前端/路由改动可只 up -d）
docker compose build && docker compose up -d
# 2.5 确认启动无报错
docker compose logs -f app
```

启动日志看到 `seeded owner user` 且无 Traceback 即正常，按 `Ctrl+C` 退出日志跟踪。

## 3. 首次启动自动迁移

新版本启动时会自动执行幂等迁移（`init_db` 内置），**无需手动操作**：

- `reviewed_at` 回填：审核门禁上线前库内已有题目全部回填为「已审核」，保持可见；**不会出现题库消失**
- 数据表缺列/旧约束的兼容迁移同样自动完成

## 4. 验证清单（本次版本）

> 审核门禁改动说明（P0/P1 修复，详见《待审核入库修复方案.md》）：回填迁移改为一次性
> （`PRAGMA user_version` 标记），重启不再批量审批待审核题；普通题库页只显示已审核题。
> **更新前请先记录当前待审核题数**（审核页「待审核」列表总数），更新后对比，应保持不变。
> 若更新后审核队列被清空（旧版本已被自动审批的库），到审核页「已审核」列表点「标记为待审核」人工撤回。

| 项 | 验证方式 | 预期 |
|---|---|---|
| 审核门禁 | 侧边栏点「立即更新」→ 完成后提示「已爬取 X 条面经，生成 Y 题待审核」；「题库审核」入口出现待审核数徽标 | 新题不直接进题库：题库页「共 N 题」不因本次更新增长，新题只出现在审核队列 |
| 重启不自动审批 | `docker compose restart app` 后再看审核队列 | 待审核题数不变（回填迁移仅执行一次，不会在每次启动批量审批） |
| 审核队列 | 打开审核页 → 默认「待审核」列表；点「通过审核」后题目从队列消失 | 已审核题在题库/今日可见 |
| 撤回审核 | 审核页「已审核」列表 → 点「标记为待审核」 | 题目回到待审核队列，题库页不再显示 |
| 存量题库 | 题库/今日页刷新 | 原有题目全部可见（一次性回填生效） |
| 提交按钮 | 答完一题 → 返回列表 → 再选一题 | 提交按钮可直接点击（修复） |
| 数据 | `docker compose exec -T app python -c "import sqlite3; c=sqlite3.connect('/app/data/interview.db'); print(c.execute('SELECT COUNT(*) FROM questions').fetchone()[0])"` | 题目数 ≥ 部署前 |

## 5. 回滚

```bash
cd /opt/interview-assistant
# 用旧版本代码包重新解压覆盖（同样恢复 .env 后重建）
docker compose build && docker compose up -d
```

数据层：备份 zip 在 `backups/`（每日 cron）或本地 `interview_backup_*.zip`，需要时可 Web「导入备份」整库回退（导入后需 `docker compose restart app` 重种 owner）。

## 6. 注意事项

- 更新前建议手动跑一次备份：`/opt/interview-assistant/backup.sh`
- 上传前先在本地过一遍测试：`.venv\Scripts\python.exe -m pytest tests -q`（382 用例全绿再打包）
- 浏览器可能有静态资源缓存：更新后强刷（Ctrl+F5）；审核页/主题 CSS 已带版本号参数
- 牛客源：生产/公开实例不启用（`sources.nowcoder_enabled=false`），历史 `.env.bak` 若残留 `NOWCODER_COOKIE` 可清理；本地个人学习需启用时仅在本地改 `config.yaml` 为 `true`
