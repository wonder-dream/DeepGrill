## 2. 准备（本地）

```powershell
# 1. 本地 Web 导出备份（含题库/知识块/账号/判分）—— 或脚本：uv run python -c "..."
# 2. 打包部署包（排除 .env/data）
tar -czf deploy_package.tar.gz --exclude=.git --exclude=.venv --exclude=data --exclude=backups --exclude="__pycache__" --exclude="*.pyc" --exclude=.env .
# 验证无敏感文件
tar -tzf deploy_package.tar.gz | Select-String "env|\.db"
```

## 3. 部署（服务器 Workbench）

```bash
cd /opt/interview-assistant
cp .env /root/.env.bak                                    # 备份当前环境变量
tar -xzf /root/deploy_package.tar.gz                      # 解压新代码（覆盖）
cp /root/.env.bak .env                                    # 恢复 .env
docker compose build && docker compose up -d              # 重建容器（TZ 生效 + faiss-cpu 安装）
docker compose logs -f app                                # 观察启动日志（迁移/索引构建）
```

## 6. 数据策略（待用户确认）

服务器现有库含：用户（本地 owner + 朋友账号）、picks、少量答题数据。

- **方案 A：整库覆盖**（Web 导入本地备份 zip）——题库/知识/本地账号全部替换；**服务器朋友账号丢失**（需重新注册），服务器旧答题数据由 §4 备份保留
- **方案 B：保留服务器用户，定向迁移**（扩展 `migrate_questions_from_backup.py` 搬 questions + knowledge_chunks，不动 users）——朋友账号保留，但本地知识库/题目与服务器用户并存，复杂度高
- 推荐 **A**（朋友数据价值低、重新注册即可；A 链路成熟：B8 校验 + 同用户名补 token）

## 7. 回滚

- 代码：`git stash`/重新解压旧包 + `docker compose build && up -d`
- 数据：用 §4 备份的 `interview_server_before_import.db` 恢复（Web 导入该备份）
- 知识库：`knowledge_meta.version` 可回退（不必要，重建即可）

## 8. 注意事项

- 打包**必须排除 .env**（A1 教训）；`.env.bak` 已备份则无风险
- faiss-cpu 构建需服务器能访问 PyPI（原构建已用 PyPI ✓）
- 首次判分会触发知识索引构建（2394 块 1-2s，自动）
- 知识库数据在 DB 内（导出/导入天然携带），无需单独同步文件
