## 0. 一句话现状

一个**功能完整度相当高、非 Web 层工程质量好、Web 层与工程卫生严重欠债**的个人求职刷题工具：
14 个业务模块 + RAG 知识库 + 多用户 + 审核门禁 + UGC 全部跑通，471 个离线测试；
但 `app/web/routes.py` 单文件 3033 行（`create_app` 单函数 1751 行）、根目录 `pytest` 已无法运行、
生产环境无 TLS、文档事实源失效。

**重构的核心判断**：痛点集中在 **Web 层缺分层** 与 **工程卫生失控**，
**不是**算法层或数据模型 —— 后者反而设计克制、且含大量只能靠实测标定的常量（见 §5），**重写时须逐项迁移，不要重新发明**。

### 3.5 认证与安全机制（✅ 已实现的，重构须保留）

- **密码**：`hashlib.scrypt`（n=2^14, r=8, p=1），格式 `scrypt$salt_hex$digest_hex`，`hmac.compare_digest` 比对
- **Token**：`secrets.token_hex(32)`，DB 存 `sha256(token)`，TTL 30 天，惰性删除过期行、可撤销
- **Cookie**：HttpOnly + SameSite=Lax + `COOKIE_SECURE` 环境开关；兼容旧 `Authorization: Bearer`
- **CSRF**：自定义头 `X-Requested-With: fetch`（跨站表单无法附加）+ SameSite 纵深
- **限流**：内存滑动窗口；`reserve/settle` 模式——**4xx 释放额度，只有真正执行的请求计数**
- **XSS**：复习卷 HTML 走 bleach 白名单；`_like_escape` 转义 LIKE 元字符 `% _ \`
- **越界防护**：`schemas.IdPath`（1..1e15）覆盖全部整数路径参数；`page` 1..1e8
- **生产硬化**：`ENABLE_DOCS` 未设则禁 `/docs` `/redoc` `/openapi.json`

## 4. 业务能力清单（重构的功能基线）

必须完整复刻的能力，按域分组：

**出题与题库**
- 三源采集：GitHub（config 列表 git pull + **SPDX 许可白名单**，无许可整仓跳过 + 来源溯源三列）、手动导入 CLI、牛客（**默认关闭，生产禁用**）
- 清洗：去 HTML/script/style、广告/水印关键词整行滤除、按「一面~十面」拆轮次
- 生成：面经→knowledge/design（按轮次分批防 max_tokens 截断）、简历→project；**随题产出 good/bad criteria**
- 入库前质量筛选：LLM 批量 20/批判定 keep/rewrite/delete，只留 keep（失败保守保留）
- 语义去重：归一化哈希快速路径 + bge-m3 余弦 0.85
- **人工审核门禁**：新题 `reviewed_at=NULL` 进队列，owner 在 `reviewer.html` 审核后可见；AI 建议快照预填
- 题库浏览：分页 + 关键词/难度/题型/标签/状态/排序筛选；owner 批量删除（跨页累积）

**答题与判分**
- 今日选题（懒加载）：按 D8 配额 + 每用户池 + 岗位×语言个性化 + 薄弱点加权
- 追问链：五层深度阶梯 L1-L5 + 三档（light/medium/deep）+ 质量驱动收尾 + 断点恢复
- 四维判分（D17）+ 评语 + 参考答案 + 薄弱点标签
- **三处 RAG 注入**：判分（标准参照）、追问（缺口核对）、复习卷（要点核对）
- 参考检索注入：库内同类题高分回答（真实回答优先，reference_answer 兜底）

**复习与个人化**
- 薄弱点聚合（`weak_tags` Counter）→ 按标签复习列表（未做优先）
- LLM 复习讲义（markdown→HTML，1h 内存缓存，同 key 并发合并防双份 LLM）
- 收藏、历史（日期分组+筛选+删除）、统计面板（30 天趋势）
- 求职设置：focus（5 岗位）+ focus_lang（仅 backend，4 语言）只影响推荐排序

**多用户与运营**

### 5.3 关键算法逻辑（须等价复刻）

1. **岗位×语言相关性判定**（`db.py:293-344`）：由标签分类的 `lang`/`roles` 推导四元组 `(lang命中, role命中, 存在语言无关分类, 命中通用分类)`；backend 严格语言原则——其他语言分类**严格排除**，无标签题兜底算相关。
2. **加权抽样** `_weighted_sample`（`db.py:347-365`）：3:1 概率从相关池抽，池空互转，不放回。
3. **追问收尾判定** `_should_finish`（`chain.py:156-192`）：LLM 自觉 finish / 轮数上限 / **档位兜底**（LLM 违反 prompt 时强制收尾）；⚠️ `prev_quality` 必须在 persist 之前查询，否则读到本轮自己。
4. **LLM JSON 容错** `_strip_trailing_commas`（`llm_client.py:14-46`）：手写状态机清理尾逗号（`[1,2,]`），**字符串内逗号与转义引号不受影响**；📄 根因是 9 个解析失败源。
5. **薄弱标签归一** `_normalize_weak_tags`（`judge.py:142-160`）：词表内保留；词表外与某词有**互为子串**关系则映射（「Java 并发」→「Java」）；否则丢弃（能力词如「深度不足」无映射）。
6. **去重降级** `dedup`（`dedup.py:23-35`）：embedding 失败 → 仅哈希精确去重，**宁重复勿丢题**。
7. **质量筛选降级**（`quality.py:63-66`）：批次 LLM 失败 → **保守保留全部**。
8. **知识索引自愈**（`retrieval.py:236-244`）：查询前比对 `knowledge_meta.version`，变更则重建；降级链 faiss → numpy 暴力 → 空。
9. **原子整数校验**：`tags.py:227-238` 用**切片赋值 + 整体替换**避免并发读到中间态——注释明确「clear 与 update 之间的空窗口会让并发读迭代崩溃」。
10. **Embedder 双检锁**（`embed.py:57-72`、`routes.py:97-103`）：进程级单例，注释写明「双份 ~4.6GB 会打满 4C8G」，**勿改回每次新建**。
