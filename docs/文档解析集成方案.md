# 上传支持 PDF / DOCX / DOC（MinerU + LibreOffice）集成方案

> 状态：已确认，实施中 ｜ 日期：2026-08-09
> 前置：独立 demo（demos/parse_demo.py）已验证通过（PDF/DOCX/DOC 全链路解析质量 OK，人工审查通过）

## 1. 解析引擎

- **PDF / DOCX**：MinerU（`pip install mineru[pipeline]`，VLM 引擎 GPU 加速；首次自动下载模型 ~1.2GB）
  - 调用方式：**CLI subprocess**（`mineru -p <file> -o <outdir>`，对 MinerU API 漂移免疫，demo 同款）
  - Windows 无 symlink 权限时 HF 缓存自动降级为复制模式（已验证可用）
- **DOC**：LibreOffice headless 转换（`soffice --convert-to docx`，已 winget 安装官方源）→ MinerU
- **MD/TXT**：直接解码（utf-8-sig/gbk，复用 importer 逻辑）
- 新增 `app/parsers.py`：`extract_text(filename, data: bytes) -> str`（从 demo 提炼，懒加载不拖慢启动；文本上限截断保护）

## 2. 上传接口改造（POST /api/upload）

- 扩展名允许 `.md .txt .pdf .doc .docx`；大小限制 2MB → **20MB**（base64 解码后字节）
- body：文本文件走 `content`（兼容旧调用）；二进制文件走 **`content_base64`**
- 流程：
  - **文本格式（md/txt）**：现有逻辑不变（direct/facejing/resume 直接执行）
  - **二进制格式（pdf/docx/doc）**：返回 `{mode: "parsing", token}` → 后台线程 `extract_text` → 解析完成后按 type 继续走现有流程（resume→候选 token；direct→入库+后台校验；facejing→后台生成）→ 任务状态存 `_upload_tasks[token]`
- `GET /api/upload/status/{token}`：轮询 `{status: parsing|done|failed, mode, count, source_id, error}`；resume 完成时带 `candidates_token` 继续候选确认流程
- 线程内直接调用后台任务函数（BackgroundTasks 是请求作用域，线程中不可用）

## 3. 前端（上传页）

- `accept=".md,.txt,.pdf,.doc,.docx"`
- 二进制文件 FileReader → base64 → `{filename, content_base64, type, count}`
- 响应 `mode=parsing` → 轮询 `/api/upload/status/{token}`（每 2s，最长 10 分钟）→ done 后：direct 显示入库数+去题库 / facejing 显示后台生成中 / resume 继续候选轮询与确认（现有流程）
- failed → 页面展示错误

## 4. 依赖与配置

- `requirements.txt` 增加：`mineru[pipeline]`、`torchvision==0.21.0+cu124`、`accelerate`（与现有 GPU torch 2.6.0 匹配，不覆盖）；`requirements.lock` 重新 compile
- LibreOffice 系统依赖（已装）：`C:\Program Files\LibreOffice\program\soffice.exe`（parsers 中按候选路径探测，缺失时 DOC 报错提示安装）

## 5. 测试

- parsers：md/txt 解码、扩展名分发、不支持后缀报错、DOC 缺 LibreOffice 报错（pdf/docx/doc 真解析由 demo 覆盖，不依赖测试环境模型）
- upload 接口：二进制上传 → parsing → 轮询 status（monkeypatch extract_text 避免真调 MinerU）→ direct/facejing/resume 各分支
- 全量回归
