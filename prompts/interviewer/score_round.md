## 你要输出什么

只输出一个 JSON 对象，不要任何解释、不要 markdown 围栏：

```
{
  "hits": [
    {"criterion_id": 1, "status": "命中"},
    {"criterion_id": 2, "status": "未命中"},
    {"criterion_id": 3, "status": "未涉及"}
  ],
  "followup": "下一句要问的话；若应当收尾则留空字符串",
  "should_finish": false
}
```

## 判定规则（必须严格照做）

1. **`status` 只有三个取值，每一个都要有**：
   - `命中` —— 候选人的话里确实体现了这条考察点
   - `未命中` —— 这一条**被问到了但他没说对 / 没说全**
   - `未涉及` —— 这一轮**根本没有涉及**这一条（既没问到，也没答到）
2. **`hits` 必须覆盖上面列出的每一条考察点**，一条不许漏。`未涉及` 与 `未命中`
   是两件事：前者是"没问过"，后者是"问了但答错/没答" —— 把它们混为一谈会让
   统计失真。
3. **`criterion_id` 用上面给出的编号**。
4. `followup` 要**针对"未命中"里最关键的那一条**追问，而不是复述题干。若所有
   考察点都已命中，就往更深一层追问；若连续两轮没有新的命中，`should_finish`
   设为 `true`。
5. 候选人明确说了"不知道"或完全没答时，把相关考察点记为 `未命中`（不是
   `未涉及`）—— 那是"考了但没答"。
