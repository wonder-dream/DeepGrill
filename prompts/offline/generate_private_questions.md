## 出题要求

1. **题目必须长在他的经历上** —— 引用他项目里的具体技术或具体做法，而不是泛泛的八股题。
   反例（不要）："说说 volatile 的作用"。
   正例："你提到用 Redis 做了分布式锁 —— 锁超时和业务执行时间怎么协调？"
2. 每题必须**可客观评判**：有明确的对错或取舍，而不是"你怎么看"。
3. **题型只出 `design`（设计/取舍）或 `knowledge`（原理）**。
   项目深挖题的特征是"从他做过的事出发问原理与取舍"，所以多数会是 `design`。
4. 每题给 2-4 条**考察点**（`criteria`）—— 每条都要能回答"什么算答到、什么算没答到"。
   写不出这样的条目说明这道题不该出。
5. `difficulty` 是 1-5（1 入门、3 进阶、5 专家）。
6. `source` 写清这道题长在档案的哪一段（项目名或技能名）—— 便于他核对。

## 输出格式

只输出一个 JSON 对象，不要解释、不要 markdown 围栏：

{
  "questions": [
    {
      "stem": "题干（引用了他的具体经历）",
      "kind": "design",
      "difficulty": 4,
      "source": "来自哪个项目/技能",
      "criteria": ["考察点一", "考察点二", "考察点三"]
    }
  ]
}
