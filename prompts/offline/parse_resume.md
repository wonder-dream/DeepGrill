## 输出格式

只输出一个 JSON 对象，不要解释、不要 markdown 围栏：

{
  "headline": "一句话概括这个人（岗位方向 + 年限量级）",
  "projects": [
    {
      "name": "项目名",
      "role": "他在这项目里的角色",
      "tech": ["用到的技术"],
      "highlights": ["他做过的具体事情，尽量保留原文里的量化结果"],
      "probe_points": ["面试官值得深挖的点 —— 写成人话，不要写成题目"]
    }
  ],
  "skills": ["他自述掌握的技术"],
  "years": "年限量级（如「3-5 年」；简历里看不出就写「未提及」）"
}

## 规则（严格照做）

1. **只依据原文**。原文没说的不要脑补 —— 宁可 `skills` 为空数组，也不要替他想。
2. `probe_points` 是这个项目里**最值得被追问**的地方：含糊的职责、只有结论没有
   过程的成果、量化的数字怎么来的。**不要写成题目**，写成"值得问什么"。
3. 保留原文里的量化结果（"QPS 提升 3 倍"这类）—— 那是后面挖深的入口。
4. 一份简历可能有多段经历，`projects` 按原文顺序全部列出。
5. 这是**隐私数据**：不要遗漏、也不要修饰，解析结果只给本人使用。
